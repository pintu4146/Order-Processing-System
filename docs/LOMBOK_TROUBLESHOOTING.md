# Lombok Annotation Processing — Troubleshooting Guide

## Problem

After adding Lombok annotations (`@Data`, `@Builder`, `@Slf4j`, `@Getter`, `@Setter`, `@RequiredArgsConstructor`) to Java source files, `mvn clean compile` fails with dozens of **"cannot find symbol"** errors.

### Symptoms

```
[ERROR] cannot find symbol
  symbol:   method builder()
  location: class com.orderprocessing.model.Order

[ERROR] cannot find symbol
  symbol:   method getCustomerName()
  location: variable order of type com.orderprocessing.model.Order

[ERROR] cannot find symbol
  symbol:   variable log
  location: class com.orderprocessing.service.OrderServiceImpl
```

Every method that Lombok should have generated (`builder()`, `getX()`, `setX()`, `log`) is missing. The compiler sees Lombok as a regular dependency but **never invokes its annotation processor**.

---

## Root Cause

### Maven 3.9+ changed annotation processor discovery

In **Maven 3.9+** (we are on **3.9.9**), the `maven-compiler-plugin` no longer automatically discovers annotation processors from the compile classpath. This is a deliberate change for build reproducibility.

**Before Maven 3.9:**
```
classpath has lombok.jar → compiler auto-detects META-INF/services/javax.annotation.processing.Processor → Lombok runs
```

**After Maven 3.9:**
```
classpath has lombok.jar → compiler IGNORES it unless explicitly registered → Lombok never runs → "cannot find symbol"
```

### Why `<optional>true</optional>` made it worse

The original `pom.xml` had:
```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>  <!-- Not guaranteed to be on processor path -->
</dependency>
```

`<optional>true</optional>` means "don't transitively include this." Combined with Maven 3.9's stricter processor discovery, the compiler never sees Lombok as a processor.

---

## Fix

### 1. Explicit `annotationProcessorPaths` in `maven-compiler-plugin` (THE FIX)

Add this to `pom.xml` inside `<build><plugins>`:

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <source>17</source>
        <target>17</target>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>${lombok.version}</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

This explicitly tells the Java compiler: **"Use Lombok as an annotation processor during compilation."**

### 2. Change Lombok scope from `optional` to `provided`

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <scope>provided</scope>  <!-- Available at compile time, excluded from runtime JAR -->
</dependency>
```

`provided` is semantically correct: Lombok is needed at compile time (to generate code) but not at runtime (the generated bytecode is self-contained).

### 3. Define the version property

```xml
<properties>
    <lombok.version>1.18.32</lombok.version>
</properties>
```

Spring Boot 3.2.5 manages this version, but the `annotationProcessorPaths` block needs it explicitly since it doesn't inherit from the dependency management section.

If `mvn clean compile` passes, Lombok is working.
